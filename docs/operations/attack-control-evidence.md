# Attack and control evidence

This workflow exercises evidence semantics and safe local syscall observations. Software replay and live sensor results are separate artifacts. A successful fixture does not establish live capture or detection coverage.

## Contracts and bounds

The catalog in `experiments/attacks/catalog.py` carries content hashes, paired labels, observable prerequisites and source references. Replay covers renamed writable execution/network, approved helper controls, executed memfd versus creation only, positive sensitive writes versus zero-byte/open-only/approved maintenance, PID reuse, epoch/namespace changes, cross-host records, missing identity and long-lived processes. Shell composition and padding strings are inert parser observations; distribution-level attack sensitivity belongs to the scoring evaluation.

`porygon.runtime-evidence.process-context` adds preceding successful exec records separately from in-window events. It queries exact host, container, sensor instance/epoch, namespace start, PID and process start. Latest successful execution before each action wins. The lookup is bounded to 512 keys, 2,048 context rows and four ancestor levels; it never searches an unbounded same-PID history. The supporting composite partial index belongs to the additive rule-workbench migration. Context can be `complete`, `truncated` or `unavailable`; complete means the bounded lookup completed, not that the sensor captured every event. Missing or truncated context does not supply inferred causal edges. Records outside the window do not independently emit findings or count as new executions in advisory features.

Exact observed lifetime attribution has no arbitrary 120-second expiry. A long-lived process retains its observed image identity until a later successful exec in the same exact lifetime. This is distinct from temporal proximity, which never becomes causal evidence. Historical `porygon.runtime-evidence` bundles retain their original hashes and replay behavior, including their legacy path set. The process-context contract includes `/sbin/` and `/usr/sbin/` positive writes. EINPROGRESS remains unproven asynchronous completion; no global send/write instrumentation is enabled by this workflow.

Collector snapshots preserve actual Docker `HostConfig.PortBindings` separately from observed `NetworkSettings.Ports`. Inspector time is recorded inside the snapshot and survives cache reuse. The API attaches authenticated host/container identity; it must not substitute identity last-seen time for inspection time. Exposure requires observed running state and a successful process execution in that same current container lifetime. Running is last-observed state, not a live Docker probe. Missing, invalid or future inspector timestamps keep the state unknown and preserve last-known state separately. Terminal stop/die/destroy observations override an older cached running inspection without renewing its timestamp; an older terminal observation cannot override a later inspected lifetime. No arbitrary freshness TTL is applied. Bounded process-history truncation is exposed explicitly. Port publication plus a process name is runtime relevance, never a demonstrated vulnerable call path or exploitation. Configured-only ports, stopped/paused/dead containers, old restart executions and unknown host networking cannot establish current published runtime exposure.

## Software verification

Run only after all parallel source tracks freeze. The host environment needs Python 3.13 and the hash-locked backend and collector dependencies (`pip install --require-hashes --only-binary=:all: -r backend/requirements.lock -r collector/requirements.lock`). Set `PYTHONPATH=backend/src:collector/src` for cross-service checks. CI installs both locks. The cross-service test feeds the real collector snapshot into the real exposure helper.

```bash
PYTHONPATH=backend/src:collector/src .venv/bin/python -m pytest experiments/tests/test_attack_controls.py -q
PYTHONPATH=backend/src:collector/src .venv/bin/python -m experiments.attacks.replay --output artifacts/local/attack-validation-checks-20261102/replay.json
```

Backend container tests include `test_runtime_context.py`, `test_runtime_evidence.py`, `test_runtime_evidence_rules.py` and `test_vulnerability.py`. Collector tests include actual/configured port normalization and inspection metadata. Run these through the coordinator's isolated Compose binding and full verification battery, not the primary deployment.

## Owned live observation

The harness refuses the primary project and accepts only `porygon-service-trust`. All selected services must already be healthy and bound to this worktree. It does not start, stop or rebuild shared services. Containment must be disabled before and throughout the run. It uses the inspected cached backend image ID, never pulls an image, creates an internal disposable network and disposable targets with exact ownership labels, dropped capabilities, no-new-privileges, resource limits and no mounts. The peer carries the protected exclusion label; observable targets explicitly set it false and carry a separate owned-disposable label, so Falco can capture their syscalls. Sensitive writes affect only `/etc/porygon-owned-fixture` in a disposable layer. Memfd execution copies the installed `/usr/bin/true` into a local memfd; no exploit or payload acquisition occurs. The network peer is another owned private container.

```bash
.venv/bin/python scripts/verify_owned_attack_controls.py --compose-project porygon-service-trust --docker-context default --api-origin http://127.0.0.1:3000 --output artifacts/attack-controls/live.json
```

Use the actual inspected isolated gateway port for `--api-origin`; a mismatch fails before workload creation. The harness emits source/catalog hashes, immutable image ID, inspected stack binding, exact selected/context event IDs, sensor epoch/identity fields, expected versus actual rules, coverage and missingness. `unknown` is a non-success exit, including missing syscall/identity evidence. Both positive and paired-control observations are required. The zero-byte write control requires an observed file open and a fixed controller acknowledgement of return value zero; the sensor does not emit a zero-byte write event, and the receipt says so explicitly. Source drop coverage remains unknown. Receipts reserve a fresh 0600 file, refuse overwrite and update atomically. Cleanup attempts every owned resource even if one removal fails, and records incomplete cleanup as non-success. Exit checks require the original eight-service binding healthy and containment still disabled. No case proves CVE exploitation. No live receipt is produced by replay. On ownership drift, unavailable cached executable/image, unsafe containment mode, missing stack binding or exceeded evidence bounds, stop and report; do not broaden capture or substitute synthetic events. Cleanup removes only exact labeled resources created by the run.

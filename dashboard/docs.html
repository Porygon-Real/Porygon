Technical Reference Specification

Running and building on Porygon

Porygon instruments the Linux kernel with eBPF probes to extract syscall telemetry directly from container workloads. It pairs bounded Jensen-Shannon distance for baseline behavioral drift with an explainable machine learning classifier to detect runtime anomalies without sidecar agent overhead.

Overview

Modern container environments are designed to run predictable, repetitive microservices. When a container deviates from its intended function: spawning unobserved shells, invoking reconnaissance binaries, or altering user namespaces: traditional file scanners on disk cannot detect active in-flight execution.

Porygon approaches container observability through a multi-tiered pipeline:

  • Kernel-space instrumentation (eBPF). Intercepts execve, fork, connect, and socket operations at the syscall boundary using modern Falco kernel probes with zero user-space sidecar penalty.
  • Digest-bound behavioral baselines. Profiles historical container behavior tied strictly to cryptographic image digests (image@sha256:...) rather than mutable human tags.
  • Information-theoretic drift ($D_{JS}$). Calculates base-2 Jensen-Shannon distance across categorical distributions (process names, binaries, parent-child lineages, bigram transitions) and token novelty.
  • Heuristic classification with tree-path deltas. Evaluates 12 runtime telemetry features against a hand-authored tree ensemble, returning operational class scores and raw-space feature deltas.
  • Deterministic rule synthesis & containment. Cross-references anomalies against deterministic rules and active allowlists, triggering automated container quarantine, process termination, or network isolation.

Installation & Prerequisites

Porygon is developed on Linux (kernel 5.8+ with BTF support) and requires Python 3.11+ and Docker Engine. 

git clone https://github.com/anuruprkris/porygon.git
cd porygon
python3 -m venv .venv && source .venv/bin/activate
pip install -e backend/ -e telemetry/ -e collector/ -e scanner/ -e responder/
pytest
  • Unit test suite. The repository includes 169+ passing unit tests covering scoring algorithms, AST rule compiling, eBPF event deserialization, and containment idempotency.
  • eBPF host support. Real-time kernel event capture requires root access to attach probes via Falco or modern BPF CO-RE.
  • Database backend. Development mode supports local SQLite; production and staging use PostgreSQL 17 with connection pooling.
Kernel Requirement Note When running outside a virtualized development environment, verify that your host kernel exposes eBPF tracepoints via ls /sys/kernel/debug/tracing/events/syscalls/sys_enter_execve.

eBPF Syscall Telemetry

Porygon intercepts kernel execution without modifying container images or requiring privileged sidecars in each pod. When a process executes inside an isolated container, Falco eBPF tracepoints trigger in host kernel space:

  • Syscall interception. Intercepts sys_enter_execve, sys_enter_fork, sys_enter_connect, and file permission alterations.
  • Kernel metadata enrichment. The probe reads the calling process's kernel task_struct, extracting the cgroup identifier, host PID, container namespace PID, parent executable, and user UID.
  • Zero container overhead. Telemetry events pass through the eBPF perf ring-buffer to the userspace daemon with sub-50ms latency and minimal CPU overhead.

Workload Baseline Profiles

Porygon rejects arbitrary tag names (e.g. :latest) because mutable tags can be overwritten by attackers or CI pipelines. Instead, every profile is cryptographically bound to an OCI image digest (image@sha256:...). 

from porygon_api.baseline import build_profile_document

profile, summaries, quality, manifest = build_profile_document(
    image_digest="nginx@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc",
    start_at=start_time,
    end_at=end_time,
    window_seconds=60,
    process_events=events,
    runtime_events=[],
    minimum_process_events=10,
    minimum_nonempty_windows=2,
)

The builder compiles 6 categorical probability distributions: process_name, executable, parent_child, user_uid, runtime_action, and process_sequence_bigram.

Jensen-Shannon Distance Engine

Traditional anomaly detectors often employ Euclidean distance or black-box thresholds. Porygon grounds baseline drift in Information Theory using bounded base-2 Jensen-Shannon distance ($D_{JS}$): 

D_JS(P, Q) = sqrt( 0.5 * D_KL(P || M) + 0.5 * D_KL(Q || M) )
where M = 0.5 * (P + Q)
  • Bounded metric. Base-2 $D_{JS}$ yields a clean, symmetric score in $[0.0, 1.0]$, where $0.0$ signifies identical probability distributions and $1.0$ represents completely disjoint behavioral profiles.
  • Top-level weights. Categorical distance (50%), Token novelty (30%), Numeric z-score deviation (20%).
  • Categorical feature weights. Executable path (25%), Parent-child lineage (20%), Process sequence bigram (20%), Process name (15%), User UID (10%), Runtime action (10%).
  • Novelty tracking. When an executable appears that was completely absent from the baseline, it is cataloged as an unseen token and scaled by its proportional frequency.

Tree Ensemble Threat Classifier

The machine learning threat classification engine (porygon_api/ml_classifier.py) evaluates 60-second observation windows across 12 engineered features:

Feature Extraction Logic
jensen_shannon_drift Categorical Jensen-Shannon distance against baseline process distribution
shell_ratio Fraction of executions belonging to interactive shells (bash, sh, zsh, ash)
recon_ratio Fraction of executions matching reconnaissance taxonomy (whoami, id, uname, ip, lsof)
tooling_ratio Fraction of network or security tools (curl, wget, nc, socat, nmap, tcpdump)
priv_escalation_ratio Executions involving SUID binaries, sudo, su, or root capability elevation
unseen_executable_ratio Fraction of processes with binary paths absent from the image baseline
parent_shim_ratio Processes directly spawned by container runtime shims (indicative of docker exec)
distinct_proc_count Total number of unique binary paths observed in the time window

The model outputs heuristic scores across 5 operational classes: benign, reconnaissance, privilege_escalation, shell_escape, and suspicious_tooling, accompanied by raw tree-path feature deltas and model provenance.

Detection Rules & Allowlists

Porygon couples continuous statistical drift scoring with deterministic, verifiable rules.

Built-in Rules

Rule ID Severity Trigger Condition
POR-DET-001 HIGH Interactive shell execution inside production container without terminal allocation
POR-DET-002 CRITICAL Reverse shell payload pattern or netcat socket binding
POR-DET-003 HIGH Reconnaissance sweep execution exceeding 5 unique discovery binaries in 60s
POR-DET-004 CRITICAL Crypto-miner binary execution or high CPU-spinning stratum loop
POR-DET-005 HIGH Runtime modification of sensitive mount points (e.g. /etc/shadow or crontabs)

Custom Rule AST Compiler & Allowlists

Operators can submit custom detection expressions via POST /api/v1/custom-detection-rules. Expressions compile into safe Python AST conditions. Furthermore, when novel behavior is deemed benign, operators register an immutable allowlist entry via POST /api/v1/detection-allowlists to prevent alert noise.

Autonomous Containment

When an incident's composite anomaly score exceeds configured operator thresholds, the responder service executes deterministic containment actions against the Docker Engine API:

  • Workload pause (docker pause). Instantly freezes container cgroup CPU scheduling, preserving RAM state for post-incident forensic inspection without destroying volatile memory artifacts.
  • Process termination (SIGKILL). Terminates the specific rogue PID while leaving the surrounding container service operational.
  • Network egress quarantine. Drops egress bridge iptables chains to prevent data exfiltration or reverse shell connections.
  • Immutable audit logging. Every containment decision writes a tamper-evident audit record with execution timestamps and triggering anomaly IDs.

Attack Lab Scenarios

The built-in Attack Simulator allows operators to evaluate detection latency and containment policies against sandboxed workloads:

  • Crypto-miner execution. Spawns a digest-pinned image (quay.io/petr_ruzicka/malware-cryptominer-container) verifying high CPU-spinning loop detection and POR-DET-004 trigger.
  • Reverse shell infiltration. Simulates interactive socket redirection via netcat, testing kernel execve capture and POR-DET-002 containment.
  • SUID privilege escalation. Tests unauthorized execution of setuid binaries, root namespace alteration, and POR-DET-003 alerting.
  • Benign batch job baseline. Executes typical Alpine Linux package updates and curl health-checks to verify zero false-positive containment against standard profiles.

Limitations

  • Linux host kernel dependency. eBPF syscall capture requires kernel tracepoints and ring-buffer support (Linux 5.8+). Windows and macOS require a Linux virtual machine backend.
  • Baseline cold-start period. Accurate Jensen-Shannon distance calculation requires a representative baseline window (minimum 10 process events across 2 non-empty windows). During initial container startup before baseline convergence, the engine defaults to deterministic rule evaluation.
  • Root privilege for probe loading. Loading eBPF programs into kernel space requires CAP_BPF or CAP_SYS_ADMIN.
